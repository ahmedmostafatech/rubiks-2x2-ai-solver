## 1. فكرة المشروع

الدكتور طالب مشروع **لعبة أو تطبيق ذكاء اصطناعي مبني على Search Algorithm**.

إحنا اخترنا **كيوب روبيك 2×2**. هنعمل لعبة تقدر:

- **تخلط** الكيوب بعدد حركات تختاره.
- **تلعب** بنفسك بالكيبورد.
- **تخلي الذكاء الاصطناعي يحله** بأكتر من algorithm، وتشوف الحل بالـ animation خطوة بخطوة.
- تعرض **Hint** (أحسن حركة جاية).
- فيها **عدّاد حركات وتايمر وUndo/Redo ووضع Time-Attack وLeaderboard**.
- فيها **Benchmark**: مقارنة بالأرقام بين كل الـ algorithms (الوقت، عدد الـ nodes، طول الحل).

**ليه 2×2 مش 3×3؟**

| | 2×2 | 3×3 |
|---|---|---|
| عدد الأشكال الممكنة | حوالي **3.6 مليون** | حوالي **43 كوينتيليون** |
| أقصى عدد حركات للحل | 11 (في الـ half-turn metric) | 20 |
| ينفع نجرب BFS عليه؟ | آه | مستحيل |

الـ 2×2 صغير كفاية إننا نقارن **كل** الـ algorithms على نفس المسألة، ولسه تحدي حقيقي.

## 3. المصطلحات ببساطة

### 🧩 مصطلحات الكيوب

| المصطلح | معناه ببساطة |
|---|---|
| **2×2 / Pocket Cube** | روبيك صغير، كل وش فيه 4 مربعات بس، يعني 24 ستيكر |
| **Corner Cubie** | القطعة الصغيرة اللي في ركن الكيوب. في الـ 2×2 كل القطع أركان، وعددها 8 |
| **State (الحالة)** | "الكيوب شكله إزاي دلوقتي". زي صورة ثابتة له في لحظة معينة |
| **Permutation** | مين القطعة اللي واقفة في أنهي مكان |
| **Orientation** | القطعة دي متلفة قد إيه (0 أو 1 أو 2 لفة تلت) |
| **Fixed Cubie (قطعة مثبتة)** | بنثبت قطعة واحدة ومبنحركهاش، لأن لفّ الكيوب كله مش حل جديد. ده بيمنع تكرار نفس الشكل |
| **Move (حركة)** | لفة وش واحد: `R` يمين، `U` فوق، `F` قدام |
| **R' (بالـ prime)** | نفس اللفة بس عكس العقارب |
| **R2** | لفتين، يعني نص لفة |
| **Scramble** | خلط الكيوب بحركات عشوائية |
| **Solved** | الكيوب محلول |
| **State Space** | كل الأشكال الممكنة للكيوب. في 2×2 حوالي 3.6 مليون شكل |
| **Facelets / Stickers** | الـ 24 مربع الملون. الدالة `get_facelets` بتحوّل الـ state لألوان عشان نرسمها |
| **2D Net** | الكيوب مفرود زي الصليبة على الشاشة |

شكل الـ Net:

```
          [U]
      [L] [F] [R] [B]
          [D]
```

### 🔍 مصطلحات الـ Search والـ Algorithms

| المصطلح | معناه ببساطة |
|---|---|
| **Search Algorithm** | طريقة بتدور على الحل بين ملايين الأشكال الممكنة، زي ما تدور على طريق في خريطة |
| **Node** | شكل واحد من أشكال الكيوب اللي الـ algorithm بيبصله |
| **Nodes Expanded** | عدد الأشكال اللي الـ algorithm فتحها وبصلها. بنقيس بيه "تعب" الـ algorithm |
| **Depth (العمق)** | عدد الحركات من الخلطة للحل |
| **Branching Factor** | عدد الاختيارات في كل خطوة. عندنا 9 حركات، يعني 9 |
| **BFS** | بيبص على كل الأشكال اللي بعدها حركة، وبعدين حركتين، وهكذا. بيضمن **أقصر حل** بس بطيء ويستهلك رام |
| **Bidirectional BFS** | بنبدأ من الخلطة ومن الشكل المحلول في نفس الوقت لحد ما نتقابل في النص. أسرع بكتير وبرضه أقصر حل |
| **DFS** | بيمشي في طريق لآخره قبل ما يجرب غيره. مش بيضمن أقصر حل |
| **IDA\*** | زي DFS لكن بحد أقصى، وبيزود الحد تدريجياً. بيستخدم الـ heuristic، وذاكرته قليلة، وبيضمن أقصر حل |
| **Greedy Best-First** | كل مرة بيختار الشكل اللي "شكله أقرب للحل". سريع بس مش بيضمن أقصر حل |
| **Optimal (أمثل)** | الحل أقصر حل ممكن |
| **Heuristic** | تخمين سريع لعدد الحركات الباقية، زي ما تبص على الخريطة وتقول "فاضل تقريباً 5 كيلو" |
| **Admissible** | تخمين عمره ما بيزيد عن الحقيقة. لو قلت "فاضل 5" يبقى الحقيقة 5 أو أكتر. ده شرط عشان IDA* يطلع الحل الأمثل |
| **Relaxed Problem** | نسخة أسهل من المشكلة بنشيل منها شرط. حلها أسرع، وعمره ما يزيد عن الحل الحقيقي |
| **Pattern Database** | جدول جاهز بنحسبه مرة واحدة، فيه "أقل حركات لحل جزء من المشكلة بس". عندنا جدول للـ orientation (729 شكل) وجدول للـ permutation (5040 شكل) |
| **Visited Set** | قايمة بالأشكال اللي زرناها، عشان منلفش في دايرة |
| **Priority Queue** | طابور الأولوية. كل واحد فيه معاه رقم، والأصغر بيطلع الأول (في Python اسمها `heapq`) |
| **Complexity** | مقياس لقد إيه الـ algorithm هيكبر في الوقت والذاكرة لما المسألة تكبر |

### 🧊 `src/cube.py` (الأهم، الكل بيستورد منه)

| الاسم | وظيفته |
|---|---|
| `SOLVED` | شكل الكيوب المحلول |
| `_FAKE_SCRAMBLED` | شكل وهمي مخلوط، عشان الواجهة يبقى عندها حاجة غير المحلول ترسمها |
| `MOVE_NAMES` | أسماء الـ 9 حركات: `U, U2, U', R, R2, R', F, F2, F'` |
| `MOVES` | جداول الحركات (فاضية دلوقتي، هتتعبى بالحقيقي) |
| `FAKE_SOLUTION` | حل ثابت وهمي كل الـ solvers بترجعه مؤقتاً |
| `inv(move)` | بتقلب الحركة (`R` ← `R'`). **حقيقية** |
| `apply(state, move)` | بتنفذ حركة على الكيوب وترجع الشكل الجديد. **وهمية دلوقتي** |
| `is_solved(state)` | بتسأل "الكيوب محلول؟". **حقيقية** |
| `scramble(n)` | بتخلط الكيوب بـ n حركة. **وهمية دلوقتي** |
| `get_facelets(state)` | بتحول الـ state لـ 24 لون للرسم. **وهمية دلوقتي** |

### 🔎 ملفات الـ Solvers (`src/solvers/`)

كل solver بيحمل نفس الشكل: دالة `solve(state)` بترجع `(قايمة الحركات، عدد الـ nodes)`.

| الملف | الـ Algorithm | فكرته |
|---|---|---|
| `bfs.py` | BFS | يبص على الأشكال مستوى مستوى، أقصر حل مضمون |
| `bidirectional.py` | Bidirectional BFS | يدور من الاتجاهين ويتقابلوا في النص |
| `ida_star.py` | IDA* | بحث بحد أقصى بيكبر تدريجياً وبيستخدم الـ heuristic |
| `heuristics.py` | الـ Heuristic | `build_pattern_databases()` تبني الجداول مرة واحدة، و`h(state)` ترجع التخمين |
| `greedy.py` | Greedy | يختار الشكل اللي شكله أقرب للحل (عدد القطع الغلط) |
| `__init__.py` | قاموس `SOLVERS` | بيجمع كل الـ solvers تحت أسمائها، والواجهة والـ benchmark بيقروا منه، فأي solver جديد يتضاف مرة واحدة بس |

السطر ده في كل solver:

```python
if state == SOLVED:
    return [], 1
```

معناه: "لو الكيوب محلول أصلاً، متعملش حاجة".

## 6. ليه فيه كود مكتوب؟ وإيه اللي لسه ناقص؟

الكود الموجود في المشروع دلوقتي هو **هيكل (Skeleton)**، مش حل. شبهه بدفتر فيه العناوين والخانات بس، والإجابات فاضية.

**اللي اتكتب (جاهز):**
- أسماء الملفات والدوال
- شكل المدخلات والمخرجات
- التعليقات اللي بتشرح الفكرة
- حاجات بسيطة جداً زي `inv()` و`is_solved()`
- رسم الكيوب على الشاشة، عشان نشوف شكل الشغل من أول لحظة

**اللي ناقص (الشغل الحقيقي بتاعنا):**
- أي حاجة عليها علامة `# STUB` أو `# TODO` أو جواها `pass`
- مفيش algorithm واحد متنفذ فعلاً

**يعني كل الـ algorithms والـ logic والواجهة التفاعلية لسه لازم نكتبها إحنا.** الهيكل بس عشان نتجنب كارثة الدمج في الآخر: لو كل واحد اخترع أسماء دواله لوحده، هنلاقي مفيش حاجة بتتوصل ببعض.

> 💡 كل مكان فيه `# STUB` اتعمل عشان تقدر تجرب شغلك وأنت مستني اللي قبلك يخلص. لما تخلص جزءك، **شيل كلمة STUB من التعليق** عشان نعرف إن ده بقى حقيقي.

7. (Bonus) وضع Time-Attack.

> نصيحة: ابدأ بالواجهة الثابتة، وبعدها الكيبورد، وبعدها الـ animation. الربط بالـ solver الحقيقي بييجي في الآخر.

### 🧪 أحمد علي (Features & Testing)

1. **أول أسبوع:** `MoveCounter` و`GameTimer` و`MoveHistory` (Undo/Redo). مش محتاجين غير الاتفاقية، فتقدر تبدأ فوراً.
2. **Greedy** كامل: الـ heuristic (عدد القطع في مكان غلط)، والـ priority queue، والـ visited set، وحد أقصى للـ nodes عشان البرنامج ميعلقش.
3. **الـ Leaderboard** (حفظ وقراءة أحسن 5 نتايج).
4. تفعيل الـ tests المقفولة وكتابة tests زيادة.
5. تكبير الـ **Benchmark** (أعماق أكتر، 20 خلطة لكل عمق) وعمل Charts من النتايج.

> Greedy بالذات algorithm ليه قصة حلوة: سريع بس **مش بيضمن أقصر حل** وساعات بيفشل. ده هنقارنه بـ BFS و IDA* في التقرير.

## 8. الاتفاقية بينا (الـ Interface)

دي الأسماء اللي **كلنا لازم نلتزم بيها**، علشان نشتغل بالتوازي من غير ما نستنى بعض:

| الشيء | التعريف |
|---|---|
| State | زوج `(cp, co)`: ترتيب القطع واتجاهها |
| `SOLVED` | الشكل المحلول |
| `MOVES` / `MOVE_NAMES` | الحركات التسع |
| `apply(state, move)` | ترجع الشكل الجديد بعد حركة |
| `inv(move)` | ترجع الحركة العكسية |
| `scramble(n)` | ترجع `(state, قايمة الحركات)` |
| `is_solved(state)` | ترجع True أو False |
| `solve(state)` | كل solver بترجع `(قايمة_الحركات, عدد_الـ_nodes)` |
| `SOLVERS` | قاموس بأسماء كل الـ solvers ودوالها |
| `get_facelets(state)` | ترجع قايمة 24 حرف ألوان للرسم |

**ترتيب الـ 24 ستيكر:** الأوجه بالترتيب `U, R, F, D, L, B`، وكل وش 4 ستيكرز، يعني رقم الستيكر = `رقم_الوش × 4 + الموضع (0 للـ 3)`.

**الألوان:** `W` أبيض، `R` أحمر، `G` أخضر، `Y` أصفر، `O` برتقالي، `B` أزرق.

> ⚠️ لو محتاج حاجة من الكيوب مش موجودة، **كلم أحمد مصطفى** بدل ما تكتب نسختك الخاصة.

## 12. الأورال (الامتحان الشفهي)

**2 مارك من 5** على الأسئلة الفردية! الدكتور هيسأل كل واحد فينا عن المشروع، فلازم:

- **كل واحد يفهم الأجزاء الأساسية لكل المشروع**، مش بس الجزء بتاعه.
- في آخر كل أسبوع، كل واحد يشرح جزئه للباقيين في **10 دقايق**. ده تدريب أورال من غير ضغط.
- قبل الموعد بيومين نعمل **أورال تجريبي** نسأل فيه بعض.

أسئلة متوقعة تذاكروها:

1. ليه ثبتنا قطعة واحدة في الكيوب؟
2. إيه الفرق بين BFS و Bidirectional BFS؟ وليه التاني أسرع؟
3. يعني إيه Heuristic؟ ويعني إيه **Admissible**؟ وليه الـ `max` بتاع اتنين admissible هو كمان admissible؟
4. ليه استخدمنا IDA* بدل A*؟ (الذاكرة)
5. ليه Greedy مش بيضمن أقصر حل؟
6. عدد الأشكال 3,674,160 جه منين؟ (`7! × 3⁶`)
7. إيه الـ Branching Factor عندنا؟ وإيه أقصى عمق للحل؟
8. لو الكيوب 3×3، إيه اللي هيتغير؟
9. إزاي الـ Undo شغال؟
10. إيه اللي بيقول للواجهة تعرض أنهي حركة؟
